# 9D — диагностика классификатора без переключения фильтров

**Реальный код в ветке** `dev/9d-classifier-shadow-diagnostics`:
`Source/ClassifierShadowAudit9D.h`, подключение в `Source/PluginProcessor.cpp`,
`Tools/analyze_shadow_9d.py`, тесты.

## Цель этого этапа

Сравнить старое решение и CLAP-текстовые кандидаты **на всей локальной библиотеке**.
Ни текущие фильтры инструментов, ни One-shot/Loops, ни исключение ударных,
ни карта, ни звук/пэды не должны меняться по новым оценкам.

## Когда выполняется

Только на worker thread после обычного **Refresh** или сканирования.
Сначала старый `ClapLibraryClassifier::apply`, затем **shadow CSV до
финального удаления с карты**. Поскольку есть существующий native cache,
обычный Refresh повторно использует неизменённые 512D-векторы; новый 52-промптовый
скан считает только cosine, без Python/HF, без скачивания другой модели.
Нет синхронного анализа/создания CSV при открытии Ableton.

Файл: `~/Library/Application Support/MelodicAtlas/ClassifierShadow_9D.csv`.

В файле одна строка на изученный кандидат; этапы:
- `classified_before_final_gate` — старое решение, 9D CLAP оценки и признаки петли/ритма.
  Включает кандидатов, которые **после** старой CLAP были исключены.
- `early_dsp_gate_excluded` — исключены акустическим PercussionGate до CLAP;
  реальные акустические признаки есть, **CLAP отсутствует**.
- `explicit_filename_gate_excluded` — прежний жёсткий барабанный filename gate;
  только относительный путь, **никаких выдуманных аудио/структурных оценок**.

CSV включает 9 семейств (`Keys/Synth/Bass/Vocal/Strings/Winds/Guitar/FX/Drums`),
топ-кандидата и margin, `Drums minus best melodic`, старый instrument state,
old percussion gate и признаки `legacy_is_loop`, `loop_override`,
`tempo_evidence`, `onset_activity`, `tonal_periodicity`, `rhythmic_character`.
Отдельные Winds в 9D **только диагностические**. Названия WAV пишутся как
относительные пути и корректно CSV-экранируются. Запись атомарная; не трогает
исходные файлы и сохранённые пользовательские настройки.

**Важно:** если `shadow_top_family=Drums`, это не значит, что файл действительно
ударный. Если `old_vs_shadow_drums_disagree=1`, это спор двух алгоритмов,
а не обнаруженная ошибка. Сами по себе признаки BPM/atttack тоже не дают
валидации Loop/Rhythmic. Эти задачи ещё требуют отдельного теста, 9D их
не выдаёт за исправленные.

## Последовательность проверок

1. **GitHub Actions must PASS** (Windows, macOS, Python tests) до установки.
2. Установить 9D как обычное обновление AU/VST3 и открыть существующий проект.
   Проверить сохранённые пэды и карту (никаких изменений не ожидается).
3. Нажать **Refresh**. Не удалять старый кэш и не делать полный рескан с нуля.
4. Прислать один файл `ClassifierShadow_9D.csv` из папки выше. Файл создаётся
   только после завершённого Refresh (или первоначального сканирования).
5. В нашем анализе по CSV подсчитать разногласия, группы и выбрать
   подвыборку спорных ударных/неударных, Guitar/Keys, synth/bass, loops/one-shots.
6. Если нужен компактный локальный отчёт, можно запустить:

```bash
python3 Tools/analyze_shadow_9d.py "$HOME/Library/Application Support/MelodicAtlas/ClassifierShadow_9D.csv"
```

Это создаёт `ClassifierShadowSummary_9D.json` и
`ClassifierReviewQueue_9D.csv` — служебная очередь **на проверку**,
не оценка истинной точности.

## Что будет следующим этапом — 9E

После сравнения определить небольшую **надёжно перепроверенную** выборку:
Loop/One-shot, rhythmic melodic vs actual drum loops, false hard hides,
Keys-vs-Guitar, processed Bass, Vox/FX. Отличать *source family*,
*structure* и *percussion* как независимые оси. Включить реальные пороги
и unknown/uncertain только после оценки ошибок исключения хороших звуков.
Никаких UI/DnD/цветов/динамических фильтров, пока классификатор не готов.

## Предупреждение

Один проход Refresh **не пересканирует заново** все исключённые по filename
файлы — их звук и CLAP намеренно не вычисляются в 9D. Если на ручном аудите
обнаружится ложное исключение по имени, отдельный 9E диагностический
декодер должен измерить именно подозрительную подвыборку, без изменения
жёсткой производственной политики.
