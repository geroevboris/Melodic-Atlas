# 8O — инструкция по проверке (без Python)

Этот этап НЕ внедряет новый отсекатель ударных. Цель — собрать диагностику для решения проблемы длинных drum/perc loops и устранить усреднение оттенка всех точек острова.

## Что изменено

1. Цветовая светлота отдельной точки теперь зависит от атаки **этого** файла, а не средней атаки целого острова. Острова, спектральные оси, CLAP-проекции, инструментальные фильтры и пэды не изменяются. Обновлена версия геометрии кэша до 8.
2. При Refresh после CLAP классификации на scanner thread создаётся **PercussionAudit_8O.csv** — диагностика файлов с длительностью >= 2 с, доступных для CLAP. Сохраняются относительные имена, длительность, loop-метка, оценки DSP, максимальное сходство с текущими drum-эталонами, итоговый percussion state и факт исключения. WAV не копируются и не изменяются.
3. Отсечение длительности < 2 с из 8N и имеющийся PercussionGate остаются неизменными. В 8O драм-лупы ещё могут попадать на карту — это ожидаемо, потому что пороги ещё не откалиброваны.

## Как получить отчёт

1. GitHub → Actions → Build Melodic-Atlas VST3/AU → ветка `dev/8o-drum-loop-audit-and-point-shades`; дождаться **успешной** сборки и скачать `Melodic-Atlas-macOS-Universal`.
2. Сохранить старый плагин как резервную копию, поставить экспериментальную AU/VST3 сборку, открыть в Ableton.
3. Нажать **Refresh** и дождаться полного завершения. На этом шаге создаётся отчёт.
4. Finder → **Cmd + Shift + G** → вставить путь `~/Library/Application Support/MelodicAtlas/` → открыть `PercussionAudit_8O.csv`.
5. Прислать в чат только CSV. На нём можно сопоставить текущие решения с имеющейся ручной разметкой 84 WAV. Новый слуховой опрос не нужен.

Если файл не появился, отправить лог сборки/скана: экспорт аудиодиагностики возможен лишь при активной сборке Native CLAP и завершённом Refresh.

Не вводить новую модель и не менять gate-пороги до анализа файла и проверки ошибок по сохранённой разметке.
