# 9D — динамические подкатегории и ручное исправление меток

Статус: **согласованный проект интерфейса, НЕ реализовано кодом**. Не путать с исправлением теста сборки 9C.

## Пользовательская идея

- Основные музыкальные категории остаются **стабильными**: Keys, Synth, Bass, Vocal, Strings, Winds, Guitar, FX; Unknown отдельно как состояние.
- **Подкатегории** определяются доступными звуками. Видимое меню показывает то, что действительно встретилось в конкретной библиотеке, с количеством.
- Bells / Mallets / Metallic — полезное пересечение тембра и инструмента; для начала динамические подгруппы Keys/FX, а не принудительно объявленная девятая основная категория. Проверить со слушателем, имеет ли смысл отдельный верхний уровень.
- Подкатегории нельзя определять только из названия WAV: CLAP text prompts + сходство соседей + акустические признаки + аккуратное подтверждение. «Нет уверенного класса» означает Unknown, но звук всё равно доступен в ALL и характере.
- Ручные исправления **имеют приоритет над автоматикой** и сохраняются при Refresh, переназначении координат и обновлениях. Исходные WAV никогда не перемещаются на диске.

## Совместимость с текущими действиями

**Проверено в 9C:**
- Обычный **right-click по точке сразу отправляет звук в выбранный пэд**.
- **Shift + right-click** открывает существующее контекстное меню «Assign to pad / Hide / Move to One-shots / Move to Loops».
- Механизм `AtlasOverrides` уже сохраняет `hidden` и `loopMode` по идентификатору файла, но не instrument/subgroup labels.
- Перетаскивание из карты прямо сейчас не реализовано. Пользователь хочет, чтобы оно появилось позже и не мешало управлению пэдами.

## UX, первая итерация — без drag-and-drop

1. **Shift + right-click по точке** → в уже существующем меню добавить **Change category…** и **Change subcategory…**, плюс **Reset to automatic**.
2. Подменю `Change category…`: Keys / Synth / Bass / Vocal / Strings / Winds / Guitar / FX / Unknown. Сразу показать выбранную и предлагаемую автоматически, например `Auto: Keys → Manual: Guitar`.
3. При выборе категории показать доступные **подкатегории этой группы**. Предусмотреть `Other / No subtype` (не навязывать ошибочную конкретизацию) и `Create personal subgroup…` только в нужной категории. Ручная категория может быть применена без подкатегории.
4. При ошибочном One-shot/Loop использовать уже существующее действие из этого же меню — **структура и instrument label независимы**.
5. Моментальное обновление отображения и счётчиков. **Undo** последней коррекции, затем последующие сохранённые изменения; команда **Reset to automatic** возвращает последнюю автоматическую гипотезу.
6. Optional: выделение нескольких точек с `Shift`/selection rectangle, операция `Assign category to N selected`. На первый этап только single sound, чтобы не усложнять и не ломать preview.

## UX, вторая итерация — drag-and-drop

- **Обычный left click** = предпрослушивание.
- **Left drag после небольшого порога движения** = тащим «чип» выбранного звука, а не двигаем карту; панорамирование карты остаётся на пустом пространстве (или модификаторе). Порог и gesture нужно проверить с существующим `MapCanvasGL`.
- Бросить звук на **category chip** в верхней полосе = вручную назначить основную категорию.
- Если подменю группы раскрыто, бросить на **subcategory row** = назначить группу + подкатегорию одной операцией.
- Бросить звук на **pad** = загрузить в pad; это отдельная зона назначения (как сегодняшнее plain right-click), не меняет инструментальную метку. Drag outside to DAW, if possible, must use original JUCE file drag with explicit opt-in and not block audio thread.
- Если возможна неоднозначность drag-to-pad vs filter, подсвечивать конкретную drop-zone и отменять операцию на пустой области; не выполнять скрытых перемещений.
- **Обычный right-click → pad не меняется**, пока пользователь не подтвердит изменение привычного UX.
- Никогда не использовать drag действия для перемещения WAV между папками на диске. Все изменения — метаданные плагина.

## Динамические подгруппы: технический план

1. Для каждого файла хранить автоматические скоры семей и подтипов (9C bank candidate + доп. текстовые прототипы), доказательства и `Unknown/Uncertain`.
2. Независимый index строит для каждой основной семьи предложения подтипов из **непересекающихся/overlapping** скоров (multi-tag). Количество `n` включает ручные назначения и уверенные автогипотезы. Слабые кандидаты доступны в диагностике, но не шумят в меню.
3. Порог показа подкатегории зависит от размера категории и уверенности — не от случайного фиксированного числа. Дополнительная проверка точности на per-subtype sample packs обязательна.
4. CLAP kNN/islands может обнаружить компактный **безымянный** кластер; интерфейс отображает его как `Other similar sounds` до появления достоверного имени, не придумывает `Bell` по геометрии.
5. Подкатегории на одном звуке могут быть multi-label, например `Synth Bass` и `Reese`, но **ручная основная категория по умолчанию ровно одна**; в будущем multiple families только сознательным Add tag.
6. Динамические пункты должны оставаться стабильными между Refresh и не менять label/color/map geometry из-за смещения count.
7. Сохранять ручные corrections в отдельном versioned overrides JSON/XML: `fileIdentity, baseCategoryOverride: nullable, subtypeOverrides: set, userDefinedSubgroups, updatedAt`; при повторном сканировании назначение не переписывается. По ключу file identity использовать существующее устойчивое связывание с `AtlasOverrides`, учесть rename/move invalidation, backup/migration и Undo.
8. Прежде чем делать drag, сначала запустить и проверить стабильные контекстные команды. Тест UI: click preview, plain right-click pads, Shift-right-click manage, assign category, assign subtype, undo, save/reopen, Refresh.
