# 9E — ПЕРВОЕ ИЗМЕНЕНИЕ РЕАЛЬНОГО РАСПОЗНАВАНИЯ DRUM LOOPS

**ВАЖНО: 9C и 9D были практически диагностическими. Эта ветка
реально меняет поведение:** часть длинных драм/перкуссионных лупов,
которые ранее оставались на карте, теперь исключается.

## Реализовано
- `Source/DrumLoop9EPolicy.h`: независимая консервативная политика
  решения; отдельный C++ регрессионный тест.
- `Source/ClapDrumLoopGate9E.h`: использует уже существующий встроенный
  CLAP-аудиовектор и уже упакованные 52 HF-текстовых эталона 9C.
  **Нет второй нейросети и переобучения.**
- `Source/PluginProcessor.cpp`: на обычном запуске кэш уже просканированных
  WAV пересматривается без повторного анализа аудио; на Refresh/Scan правило
  действует до существующего удаления распознанной перкуссии.
  Существующее `PercussionState::Percussive` используется текущей картой,
  поэтому старые звуки действительно исчезнут из результатов.
- Дополнительная защитная проверка: CLAP первым считает Drums именно с
  subtype `DrumLoop`, его косинус >=0.35, отрыв от **лучшего любого
  мелодического** эталона >=0.12, акустические атаки >=0.09,
  в трекинге тона <=1 надёжного окна, длительность >=2.0 сек.
  Отдельно есть veto для явно названного мелодического инструмента и
  ранее достоверно идентифицированного по метаданным инструмента.

## Измерение на ПРЕЖНЕМ кэше пользователя

Входные файлы использованы локально, не добавлялись в публичный репозиторий:
`ScannedDatabaseCache_v4.xml` (1373 записей, 1050 с длиной >=2 c),
`clap_subtype_scores(1).csv`, 84 ручные метки.

По 50 подходящим под >=2 c звукам с yes/no метками перкуссии:
- **6 из 9** отмеченных ударных скрываются новым правилом.
- **0 из 41** размеченных музыкальных звуков скрываются новым правилом.
- **67 из 1050** сохранённых подходящих звуков в целом попадут под новое
  правило. Из них **61 ранее не проверялся человеком**. Возможны ошибочные
  исключения; это не доказанная точность на независимой библиотеке.
- Три оставшихся известные пропущенные перкуссии:
  `TT_MONOLITHIC.WAV` (скрэтч),
  `EQ-B42 06 Cng Loop 090.wav` (конга, близка к мелодическим описаниям),
  `Cymatics - Organics - Chain on Plate 3.wav` (необычный металлический FX).

Текущая **9E не исправляет инструментальные подкатегории** и
**не делает новый One-shot/Loop классификатор**.
И не обещает, что все 67 автоматически исключённых — настоящие ударные.
Встроенная проверка Source + DSP консервативна, но выборка для валидации
слишком мала. Это реальное изменение vs 9C/9D, но НЕ конец работы.

## Проверка после завершённой сборки CI

Не требуется присылать CSV и вообще не требуется удалять кэш.

1. Перед установкой сохранить рабочую версию 9C и локальный кэш
   `ScannedDatabaseCache_v4.xml` на случай отката.
2. Установить **именно 9E**, проверить список объектов на карте, особенно
   `EQ-Lp926 OrgBBox Relays 090.wav`,
   `EQ-Lp929 OrgBBox Switch 090.wav`,
   `133_FGBeats_SP_15.wav`,
   `130_FGPercs_SP_21.wav`. При наличии в библиотеке это будут
   конкретные проверочные примеры, которые должны пропасть с карты.
   Можно также проверить `140_001.wav`: ручная метка была Bass, он
   **должен остаться**.
3. Проверить, что пэды, прежние фильтры, предпрослушивание, AU/VST3
   работают. Мануальные loop/hidden overrides не меняются.
4. Если обнаружен необходимый музыкальный звук, пропавший из карты,
   сообщить его имя; сначала исправляем безопасность gate, не увеличиваем
   агрессивность исключения.

**Про rollback:** исходные WAV никогда не удаляются. Для полного отката
временно вернуть 9C, затем выполнить Refresh, чтобы восстановить ранее
удалённые из производственной БД записи из файлового дерева. Не считать
старый сохранённый кэш неизменным после Refresh — сначала сделать копию.

## Следующий этап 9F (только классификация)

Сначала подтвердить фактические результаты 9E на конкретных WAV.
Затем отдельно исправлять One-shot/Loop для BPM/grid лупов без слова
`loop` в имени. По прежнему кэшу некоторые очевидно повторяющиеся
8- и 16-битовые циклы на 90/130/133 BPM ошибочно попали в One-shot,
т. к. алгоритм не всегда распознаёт числовые BPM-токены без суффикса
`bpm`. Не заменять эту проверку случайной эвристикой по длительности:
длинные FX и ноты тоже могут иметь длительность в сетку. Нужна
проверка многократных атак и структуры на реальных WAV.

Отдельные ритмические **мелодические** лупы не являются барабанными.
Инструментальные категории и dynamic subfilters менять только после
проверки источника/структуры/перкуссии.
