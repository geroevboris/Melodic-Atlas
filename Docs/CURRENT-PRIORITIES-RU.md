# Melodic Atlas — текущий согласованный план (11.11.2026)

Это единый ориентир разработки. **Не открывать новую dev-ветку на каждую правку.**
Выполнять работу в `dev/9f-grounded-loop-percussion`; `main` — стабильная
основа, не перезаписывать до проверки готовой версии. Старые ветки не
удалять без отдельной уборки/проверки, но и не использовать как рабочие.

## Порядок работ

1. **Классификация**: исключить из карты подтверждённые барабанные лупы,
   корректно отличать One-shot от Loop и ритмические музыкальные лупы
   от ударных. Обязательные WAV-регрессионные случаи:
   - `EQ9509 KikSnrLp - BRoWN.wav`
   - `093-01.wav`
   - `100_CrunchyBreaksDry_22_SP.wav`
   Все три — проверенные пользователем **DRUM LOOPS**.
   Не скрывать мелодический бас `140_001.wav`. Пользователь требует
   реальных изменений качества, а не диагностических билдов.
2. **Динамические подкатегории** внутри стабильных основных категорий:
   определяются фактическими звуками в библиотеке, не только именами WAV
   и папок. Тембров и типов может быть много; сомнительные не выдавать
   за уверенно распознанные. Выбор подкатегории должен фильтровать реально
   назначенные звуки. Самостоятельные Winds в будущем не смешивать со Strings
   без плановой миграции UI.
3. **Карта**: X — от басового музыкального регистра слева до высокого
   справа. Основной тон/музыкальный источник важнее спектрального центра:
   насыщенный верхними гармониками Neurobass остаётся слева.
   Y **не использовать attack**: сходство в исходном CLAP/UMAP пространстве,
   акустические атаки остаются только для классификации.
   Убрать светлые/тёмные оттенки по атаке, одинаковая визуальная
   насыщенность точек в одной цветовой группе.
4. **Визуальный редизайн** — в последнюю очередь после исправления
   классификации, подкатегорий и координат.

## UX для будущего (не реализовывать сейчас)

Никакого drag-and-drop точек: конфликтует с быстрым поиском карты.
Сохранить plain right-click → выбранный пэд.
После основных задач: Shift+right-click → `Move to…` →
раскрывающийся список категория/подкатегория, ручное исправление
с приоритетом над алгоритмом и сохранением после Refresh.
Не перемещать исходные WAV на диске.

## Инженерные правила

- Один источник правды для приоритетов и одна рабочая ветка.
- Новый билд только с изменением **поведения**, проверенный тестами;
  старую рабочую версию сохранить как откат.
- Кэш/пэды/проект/настройки и история не теряются; не удалять WAV.
- Все новые эвристики проверять на жёстких отрицательных примерах:
  rhythmic guitar, arpeggio, synth bass, long tonal one-shot, FX,
  bright/distorted bass. Сверхкороткие (<2s) остаются скрытыми.
- Не считать CLAP cosine вероятностью и не подменять качество
  распознавания безосновательным ужесточением порогов.
